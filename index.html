4プログラム分のプリセットを保存しておくとワンクリックで切替できます。プリセットは localStorage にこのブラウザだけに保存されます。

1. ウィジェット（リファラー登録）

スクリプト: https://tag.stg.jolt.me/widget/v1/widget.js

同一ページに3形式を並べて展開します。フル表示形式は 専用ページ を開いてください。

ウィジェットが表示されない場合: クリエイティブの公開ステータスが「公開中」になっているか確認してください。デフォルトは「停止」です。

① インライン埋め込み

下の枠内に直接展開されます。data-jolt-widget-inline を持つ要素にマウントされます。

② 要素クリックポップアップ

ボタンクリックでモーダル展開。data-jolt-widget-trigger をトリガー要素に付与します。

③ フローティング

画面右下に常時表示されるボタンが対象です（クリエイティブの「表示位置」設定で位置が変わります）。

2. 紹介リンク → 問い合わせフォーム経由のリード作成 BtoB既存

ベンダーサイトの問い合わせフォームを模した別ページ。紹介リンクをクリックして遷移してきた状態で送信すると、tracking_event → conversion → リード作成 までの既存パイプラインが動きます。Section 3 のタグ updateLeadStatus よりこちらの方が紹介ベースのリード作成に近いシナリオです。

フロー: 紹介リンククリック → fragment cookie_value を localStorage に保存 → フォーム送信 (/api/tracking/submit) → thanks ページで /api/tracking/cv 発火 → リード作成

リードフォームを開く（新規タブ）

※ 紹介リンクをコピーして末尾を ...&redirect=https://areyo-inc.github.io/jolt-widget-stg-test/lead-form/ 等にすると、リダイレクト先としてこのフォームに飛ばせます（実際の挙動はリンク設定のリダイレクト先設定に従う）。

3. タグ: updateLeadStatus BtoB

リード自動作成・ステータス更新を発火。紹介リンクをクリックしてからこのページに戻り、ブラウザに帰属Cookieが入っている状態で送信すると、リファラー（またはパートナー）経由のリードとして作成されます。

エンドポイント: POST {api-base}/api/tracking/lead-status（タグから直接呼ばれます）

public_token が未設定のためタグ送信できません。Section 0 でプリセットに public_token を保存してください。

4. タグ: track Phase 2

BtoCモード用カスタムイベントタグ。サーバー側（jolt-backend）の Phase 2 機能が未実装の場合は 404 等のエラーが返ります（タグはエラーを握り潰すためコンソールに出ません）。

エンドポイント: POST {api-base}/v1/tag/events/{signup|purchase|renewal}

サインアップ・登録完了ページに発火。リードを「適格」へ遷移させる。

購入・コンバージョン完了ページに発火。リードを「取引成立」へ遷移させ、イベント2報酬を発火する。

継続課金イベント。通常はサーバーサイドから呼び出すものですがテスト目的でブラウザから送れるようにしています。external_source / external_source_id が必須です（冪等性キー）。

5. 帰属 / 認証状態の観察

localStorage / sessionStorage の値を表示します。HttpOnly Cookie（jolt_widget_token / jolt_referral 等）は JS から読めないので、ブラウザの DevTools → Application → Cookies で確認してください。

6. テストツール

ウィジェットの認証チェックは 1セッション (=このタブ) につき1回 しか走らない仕様です。 マジックリンク認証後にこのページへ戻ってもウィジェットが未認証のままのときは、プローブをリセットしてリロード を試してください。

※ HttpOnly Cookie（jolt_widget_token / jolt_referral）は DevTools → Application → Cookies → api.stg.jolt.me / external-api.stg.jolt.me から手動削除してください。

7. 動作確認の流れ（一例）

  1. Section 0 で対象プログラムを切替
  2. Section 1 のウィジェットでリファラー登録（メアドを入力 → 紹介リンク表示）
  3. 受信した マジックリンクメール 内のリンクをクリック → 認証完了 → このページに戻る
  4. 戻ってきたら「sessionStorage プローブをリセットしてリロード」（Section 6）
  5. ウィジェットが 認証済み状態 で表示されることを確認（実績タブが詳細表示に）
  6. 別ブラウザ（シークレット） or 別端末で紹介リンクをクリック → 帰属 Cookie をセット
  7. 別ブラウザ側でリードを作成（以下のいずれか）
    • Section 2 の リードフォーム を開いて送信（既存BtoBパイプライン）
    • Section 3 の updateLeadStatus タグ送信（BtoB既存タグ）
    • Section 4 の track signup / purchase（Phase 2）
  8. ベンダーダッシュボードの「紹介」一覧で referrer_id がセットされたリード が出ていることを確認
  9. リード → 適格 → 取引成立 と進めて報酬が発火することを確認
  10. リファラーをブロックして、紹介リンクから新規リードが作れなくなることを確認
